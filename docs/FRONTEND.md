# Frontend architecture and implementation guide

This document covers the interactive user interface in [index.html](file:///Users/sonil/Desktop/HyLeakAI/app/web/index.html). The single-file HTML frontend serves as the public face of the project, replacing the Streamlit research tool for deployment.

---

## Summary

The web application provides a single self-contained HTML page that requires no build step or bundled dataset. It presents the pipeline through four integrated panels:

1. **Storage Atlas:** Displays candidate site suitability rankings.
2. **Breathing Reservoir:** Visualises pressure and saturation field dynamics.
3. **Risk and Attribution:** Displays XGBoost leakage risk probabilities and feature attributions.
4. **Geologist Site Input Screen (Geologist Workbench):** Accepts user site scalar parameters (area, thickness, porosity, efficiency, caprock parameters) and computes volumetric capacity, pressure ceilings, and feasibility flags via `POST /v1/site-screen`.

The application supports two operating modes:

- **Preview mode:** Client-side static execution using procedural stand-ins. It loads without a backend service.
- **Live model mode:** Requests inference outputs from the FastAPI service in [main.py](file:///Users/sonil/Desktop/HyLeakAI/api/main.py) on Google Cloud Run (`https://hyleakai-152424867743.asia-south1.run.app`).

### Panel data sources

| Panel | Status | Data source |
|---|---|---|
| **1. Storage Atlas** | Real | Embedded data from `outputs/site_suitability_ranking.csv` generated by [site_suitability.py](file:///Users/sonil/Desktop/HyLeakAI/src/site_suitability.py). Scores update live when adjusting criteria weights. |
| **2. Breathing reservoir** | Illustrative / Live API | Displays spatial fields and plume evolution. In Live mode, calls `GET /v1/fields/{simulation_id}` for real surrogate predictions. |
| **3. Risk / attribution** | Real in Live mode | In Preview mode, displays real feature names from `outputs/shap_features.json` with illustrative values. In Live mode, calls `POST /v1/assessments` for real U-Net + XGBoost risk scores. |
| **4. Geologist Workbench** | Real | Sends scalar site parameters to `POST /v1/site-screen` and renders effective capacity, planned mass, pressure limits, and risk flags. |

Per-panel badges clearly state whether a panel displays static preview data or live API results.

## Design direction

The core design principle treats the interface as **an instrument, not a static dashboard**. The pipeline transforms multi-hour reservoir simulations into sub-second screening passes. The visual decisions enforce this concept:

1. **Dynamic plume timeline:** Ten annual injection and withdrawal cycles form a natural rhythm. The cycle ribbon allows users to scrub across 60 timesteps banded by stage.
2. **2.5D slab representation:** Extruding the 7,680 m × 7,680 m domain under a seal highlights how fault surfaces intersect caprock boundaries.
3. **Spatial fault swarm:** Rendering fault segments directly on the plan view shows how dangerous faults align with pressure ridges and plume fronts.
4. **Data provenance chips:** UI chips tag every metric as dataset-derived, calculated, or assumed based on definitions in [config.py](file:///Users/sonil/Desktop/HyLeakAI/src/config.py).
5. **Interactive weighting:** Adjusting suitability weights reshuffles site rankings live, emphasizing how assumptions influence site selection.
6. **Latency reporting:** Every computation measures and displays execution time using `performance.now()`.
